What is Stego Mail?

Steganography means hiding a secret message inside something that looks ordinary, so nobody even suspects a secret exists. Stego Mail lets you send a friend a normal-looking picture or sentence with a message hidden inside it.

Encryption alone

Turns the message into gibberish like x7#kQ9…. Anyone can see that something secret is being sent.

Steganography

The message travels inside a sunset photo. Anyone looking sees only a sunset.

Stego Mail does both: it hides the message, and if you add a password it also encrypts it. Even if someone finds the hidden data, they can't read it.

The server stores only the picture or text that carries the message, never the message itself. It is read out of the carrier only when the recipient presses Reveal.

How we hide a message in a picture

The basic idea: the last bit

A picture is a grid of pixels. Every pixel has three colour values, Red, Green and Blue, each a number from 0 to 255 stored as 8 bits. The last bit is the least important: changing it moves the value by only 1, which no eye can see.

Red = 204 = 11001100  →  11001101 = 205

The simplest method (called LSB, least significant bit) writes one message bit into the last bit of every colour value, starting at the top-left. It works, but the changes are crowded together at the top of the picture, and statistical tools can spot them. Our app (Member 1's code) improves this in four ways:

1

Hide only in "busy" areas

The picture is cut into 8×8 tiles. Each tile gets a "busyness" score: how much neighbouring pixels differ (leaves, waves, hair score high; clear sky scores low). Only the busier half of the tiles is used, because tiny changes vanish in texture but could stand out in a smooth area. The score ignores the last bit, so the receiver can rebuild the exact same map from the received picture.

2

Matrix embedding: 3 bits in 7 values, at most 1 change

The usable colour values are put into groups of 7, numbered 1 to 7. Take the numbers of all values whose last bit is 1 and combine them with XOR. The result is a 3-bit number, and that number is the hidden data. To make it equal the 3 bits we want, we only ever need to change one value by 1 (or none, if it already matches).

Plain LSB would need 3 values for 3 bits and change about 1.5 of them on average. Ours changes at most 1 in 7, so the picture is disturbed far less.

3

Scatter the bits in a random order

The groups are not used top-to-bottom. A random-looking order is generated from a salt (16 random bytes chosen for every message) and, when locked, from the password too. So every picture uses different pixels, spread across the whole image.

4

A small header in front

Before the message, the app hides a 43-byte header: the tag ILAB (so the app recognises its own pictures), version, method, whether it is locked, the message length, the salt, the encryption nonce, and a CRC check value. The header always uses a fixed public order so the receiver can find it first, then it tells them where and how much to read.

Finally, the app checks its own work: before sending, it extracts the message from the finished picture and makes sure it matches exactly.

How we hide a message in text

Unicode, the system computers use for all the world's letters, includes characters that are completely invisible and take up no space. They exist for languages such as Arabic and Persian, to control how letters join. Our app (Member 2's code) uses four of them, so each invisible character carries 2 bits:

00 U+200B Zero Width Space
01 U+200C Zero Width Non-Joiner
10 U+2060 Word Joiner
11 U+2063 Invisible Separator

If the cover has Arabic letters, only U+200B and U+2060 are used, 1 bit each, so the hidden run never sits between joined letters.

  1. The secret becomes bytes. Each byte (8 bits) becomes 4 invisible characters (8 in Arabic text).
  2. In front goes a tiny header: the tag TS and the message length, and an unlocked message ends with a CRC check. A locked message uses the tag TL and carries the salt, nonce and an authentication tag instead.
  3. The invisible run is slipped in right after the first word of your cover sentence.

The sentence looks exactly the same on screen and survives copy and paste in many apps.

The text gets longer: a 10-letter secret adds 72 invisible characters (224 with a password, twice as many in Arabic text). A character counter or Unicode scanner would notice, and some apps (or retyping the text) remove them. The visible words never change.

The password lock

Pictures and text use the same lock:

  1. Your password and the random salt go through scrypt, a deliberately slow function that turns a password into a 256-bit key. Being slow makes guessing passwords expensive.
  2. The message is encrypted with AES-256-GCM. GCM also adds a 16-byte "seal" (authentication tag): if the password is wrong or one bit of the carrier was changed, the app refuses instead of showing garbage.
  3. For pictures, the password also decides which pixels hold the message.

Share the password another way, for example by phone. Without a lock, the message is only hidden, not secret: anyone with our app could reveal it.

🔍 Lab: can it be detected?

Hiding a message is only half the story. Steganalysis is the science of finding hidden messages. This lab hides the same random message in the same picture two ways, with plain LSB (the textbook method) and with our app, then attacks both with a classic detector:

The chi-square attack (Westfeld & Pfitzmann, 2000). LSB hiding makes each pair of colour values (like 100 and 101) appear almost equally often. The attack reads the picture from top to bottom and measures how "suspiciously equal" those pairs are, giving a probability from 0% to 100% that data is hidden.

Compared to existing apps

We looked at popular tools: OpenStego, Steghide, StegOnline, StegCloak and SNOW. They hide messages well, but most are "black boxes": you press a button and get a file back, without seeing what changed or why. Stego Mail adds sending to other users, a built-in gallery, a history of what you did, and this page, which shows every step using the real code.

Honest limits. No method is undetectable. A specialist with steganalysis tools may still notice hidden data, especially if they have many of your pictures. A password protects the content, not the fact that something is hidden. Never resize, crop, screenshot or convert a received picture before revealing it.
